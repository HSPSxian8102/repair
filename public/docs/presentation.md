# 國立臺南大學附屬高級中學
## 設備線上報修系統
### 系統說明簡報

---

## 第 1 頁｜系統背景與動機

### 為什麼需要這套系統？

**過去的問題：**
- 設備損壞只能用口頭通報或紙本填單，容易遺失或被遺忘
- 總務人員無法掌握全校待處理事項的整體狀況
- 報修者不知道自己的報修是否已被受理或處理進度
- 歷史紀錄無法查詢，無法進行數據分析

**解決目標：**
- 全校師生隨時隨地線上報修，不受時間地點限制
- 總務人員集中管理所有報修單，清楚追蹤每筆進度
- 系統自動發送 Email 通知，減少人工聯絡成本
- 留存完整歷史紀錄，支援數據統計分析

---

## 第 2 頁｜系統核心特色

### 六大亮點功能

**① 學校帳號直接登入**
使用學校 Google Workspace 帳號登入，不需另外申請帳號，系統自動限制非學校帳號登入。

**② 即時 Email 通知**
- 新報修提交 → 所有總務人員立即收到通知
- 維修完成 → 提報者自動收到完成通知

**③ 兩層式地點設計**
管理員只需維護大樓／場域名稱，報修者自行填寫詳細位置，大幅降低管理成本。

**④ 完整狀態追蹤**
待處理 → 處理中 → 已完成，每個階段都有時間戳記與處理人員記錄。

**⑤ 統計儀表板**
圓餅圖、長條圖、平均處理時間，一目了然掌握全校設備健康狀況。

**⑥ 自動封存機制**
完成超過 12 個月的報修單自動封存，系統輕量高效，資料永久保留。

## 第 3 頁｜技術架構概覽

### 採用現代雲端技術，維運成本極低

**前端（使用者介面）**
- React 18 + Vite — 快速、響應式的網頁應用
- Tailwind CSS — 乾淨的視覺設計，支援手機版
- 部署於 GitHub Pages — 完全免費

**資料庫與後端**
- Firebase Firestore — 即時雲端資料庫，無需自架伺服器
- Firebase Authentication — Google 帳號登入驗證
- Firebase Cloud Functions — 伺服器端自動化邏輯（Email 通知、排程封存）

**Email 通知**
- Gmail + Nodemailer — 穩定可靠，學校既有帳號即可使用

**部署與版本控制**
- GitHub — 程式碼儲存與版本管理
- GitHub Actions — 自動化 CI/CD，push 後自動部署

**費用估算：每月費用幾乎為 $0**

## 第 4 頁｜三層權限設計

### 不同角色，不同操作範圍

---

### 👤 一般使用者（全校師生）
**可以做：**
- 提交新報修單
- 查看全校所有報修單（唯讀）
- 取消自己提交的「待處理」報修單

**不能做：**
- 修改他人報修單
- 進行任何管理操作

---

### 🛠 總務人員（admin）
**除一般使用者權限外，還可以：**
- 接受報修、標記處理中 / 已完成
- 填寫完成說明
- 刪除報修單
- 查看統計儀表板
- 匯出 CSV 報表
- 查看歷史封存紀錄、取消封存

---

### ⭐ 超級管理員（superadmin）
**除總務人員權限外，還可以：**
- 新增 / 移除總務人員帳號
- 設定管理員角色（admin / superadmin）
- 管理地點清單（新增、編輯、停用、刪除場域）

---

## 第 5 頁｜報修單生命週期

### 從提交到封存的完整流程

```
[師生提交報修]
      ↓
  ● 待處理（Pending）
  ← 師生可在此階段取消
      ↓ 總務人員接受
  ● 處理中（In Progress）
  ← 記錄：開始時間、處理人員
      ↓ 標記完成
  ● 已完成（Completed）
  ← 記錄：完成時間、完成說明
  ← 自動 Email 通知提報者
      ↓ 超過 12 個月
  📦 自動封存（Archived）
  ← 仍可查閱，可手動取消封存

另外：
  ● 已取消（Cancelled）← 師生自行取消
```

## 第 6 頁｜提交報修單操作說明

### 任何師生皆可操作

**步驟一：點擊「+ 新增報修」**
登入後，點擊導覽列上方的「+ 新增報修」按鈕。

**步驟二：填寫報修標題**
簡短描述問題，例如：「水龍頭損壞」、「投影機無法開機」。

**步驟三：選擇大樓 / 場域**
從下拉選單選擇所在大樓或場域，例如：行政大樓、圖書館、操場。

**步驟四：填寫詳細位置（選填）**
選完大樓後輸入精確位置，例如：105教室、2樓男廁、舞台右側。

**步驟五：選擇類別與優先級**
類別：電器設備、水電管線、門窗玻璃、桌椅傢俱、空調冷氣、資訊設備、環境清潔、其他。
優先級：普通 或 🔴 緊急（影響教學或有安全疑慮時選緊急）。

**步驟六：填寫問題說明**
詳細描述損壞情形，最多 500 字。

**步驟七：點擊「提交報修單」**
提交後自動跳至報修詳情頁，同時所有總務人員立即收到 Email 通知。

## 第 7 頁｜總務人員操作說明

### 報修受理與處理流程

**查看待處理報修**
登入後，首頁「報修清單」預設顯示所有未封存報修單。
可依狀態篩選（全部 / 待處理 / 處理中 / 已完成）或關鍵字搜尋。

**接受報修（待處理 → 處理中）**
1. 點擊報修單進入詳情頁
2. 點擊「✔ 接受處理 → 處理中」
3. 系統自動記錄開始時間與處理人員姓名

**標記完成（處理中 → 已完成）**
1. 進入報修詳情頁
2. 填寫完成說明（選填，例如：已更換零件、待訂料）
3. 點擊「✅ 標記為已完成」
4. 系統自動發送 Email 通知原提報者

**其他管理操作**
- 搜尋特定報修單（標題、地點關鍵字）
- 篩選特定類別
- 匯出目前篩選結果為 CSV（可用 Excel 開啟）
- 刪除誤填或重複的報修單

## 第 8 頁｜統計儀表板

### 數據一目了然，掌握全校設備狀況

**總務人員及管理員可使用**

**摘要數字卡（4 個指標）**
- 全部報修單數量
- 待處理中的報修數量
- 本月新增數量
- 平均處理天數

**圓餅圖 — 狀態分佈**
直觀呈現待處理、處理中、已完成、已取消的比例。

**長條圖 — 近 6 個月趨勢**
每月新增報修數量的走勢，快速掌握是否有異常增加。

**長條圖 — 類別分佈**
各類別（電器、水電、門窗等）報修數量比較，識別最常見問題類型。

**CSV 匯出**
一鍵匯出目前篩選的報修清單為 Excel 格式，欄位包含：提交日期、標題、地點、詳細位置、類別、優先級、狀態、提交者、完成時間、完成說明。

## 第 9 頁｜安全性設計

### 多層保護，確保資料安全

**身份驗證**
- 僅限學校 Google Workspace 網域帳號（@gm.tntcsh.tn.edu.tw）登入
- 非學校帳號嘗試登入會被自動拒絕並登出
- Firebase Authentication 處理所有登入驗證，不自行儲存密碼

**閒置自動登出**
- 5 分鐘無操作自動登出，防止他人借用已登入裝置
- 監測滑鼠移動、鍵盤輸入、觸控、捲動等所有使用者操作
- 任何動作皆會重置計時器

**資料庫存取控制（Firestore 安全性規則）**
- 未登入者：無法讀取任何資料
- 一般使用者：只能讀取，建立自己的報修，取消自己的「待處理」單
- 提交者更新限制：只允許將狀態改為「已取消」，且只能在「待處理」狀態下操作
- 管理員：可更新所有報修單狀態
- 超級管理員：可管理地點清單和管理員帳號

**防誤操作設計**
- 刪除操作需二次確認
- 地點停用而非直接刪除，歷史資料不受影響
- Cloud Functions 有管理員身份驗證，防止未授權呼叫

## 第 10 頁｜Email 自動通知機制

### 讓總務人員和提報者都即時掌握動態

**通知一：新報修提交**
- 觸發時機：任何人提交新報修單
- 收件者：所有總務人員（系統自動抓取管理員清單）
- 內容：報修標題、地點、類別、優先級、問題說明、提交者、查看按鈕連結
- 緊急報修會在主旨特別標示【緊急】

**通知二：報修完成**
- 觸發時機：總務人員將報修標記為「已完成」
- 收件者：原始提報者（使用提交時記錄的學校 Email）
- 內容：標題、地點、完成人員、完成說明、查看按鈕連結

**技術實作**
- Firebase Cloud Functions（伺服器端執行，不佔用使用者瀏覽器資源）
- 部署於 asia-east1（台灣）region，延遲低
- Gmail SMTP + Nodemailer，使用 Gmail 應用程式密碼驗證

## 第 11 頁｜地點管理設計

### 兩層式架構，大幅降低維護成本

**舊的問題：一個地點一筆資料**
- 100 間教室 = 需建立 100 筆資料
- 管理員建立到崩潰
- 報修者從超長下拉選單尋找，使用者體驗差

**新的設計：大樓 ＋ 自由文字**

| 層級 | 管理方式 | 範例 |
|------|----------|------|
| 大樓／場域（第一層） | 管理員預建，下拉選單 | 行政大樓、圖書館、操場 |
| 詳細位置（第二層） | 報修者自填，文字輸入 | 105教室、2樓男廁、舞台右側 |

**優點：**
- 全校只需建立約 10～20 筆場域資料
- 報修者可以描述任意細節，靈活度更高
- 顯示格式：「行政大樓 — 105教室」，清晰易讀
- CSV 匯出時大樓和詳細位置分為兩個欄位，方便分析

## 第 12 頁｜帳號管理說明

### 超級管理員操作指南

**新增總務人員**

前置條件：對方須先以學校帳號登入系統一次（讓 Firebase 建立帳號資料）

操作步驟：
1. 點擊導覽列「👥 帳號」
2. 在「新增管理員」區塊輸入對方學校 Email
3. 選擇角色：總務人員（admin）或 超級管理員（superadmin）
4. 點擊「新增」

**調整角色**
在管理員清單中，直接點擊角色下拉選單修改，立即生效。

**移除管理員**
點擊「移除」按鈕，確認後該帳號降為一般使用者，原有報修記錄不受影響。

**注意事項**
- 至少保留一位超級管理員，避免無人可管理系統
- 移除管理員不會刪除該使用者帳號，只是移除管理權限
- 帳號管理操作由 Cloud Functions 安全執行，有完整的身份驗證保護

**GitHub Repository**

**其他學校只需修改 7 個設定：**
